Introducción

¿Qué es Podman?

Definición Podman (POD MANager) es un motor de contenedores sin daemon que permite crear, gestionar y ejecutar contenedores e imágenes OCI sin necesidad de un proceso raíz persistente.
Ventaja clave Podman puede ejecutar contenedores como usuario normal (rootless), mejorando drásticamente la seguridad del sistema host.
Compatibilidad Docker Los comandos son prácticamente idénticos a Docker. Puedes usar alias docker=podman en la mayoría de los casos.

ARQUITECTURA COMPARADA

🐳 Docker

CLI → dockerd (daemon root)
Daemon siempre activo
Requiere grupo docker
Proceso único centralizado

🦭 Podman

CLI → fork/exec directo
Sin daemon persistente
Rootless por defecto
Soporte nativo de Pods
OCI Runtime crun / runc systemd integration Pods nativo

Imagen vs Contenedor Una imagen es la plantilla de solo lectura (como una clase en POO). Un contenedor es la instancia en ejecución (como el objeto creado).
Registries Las imágenes se almacenan en registros: docker.io (Docker Hub), quay.io (Red Hat), o un registry privado como Harbor.
Verificar instalación
$ podman version
$ podman info
$ podman --help
Comando #1

podman pull — Descargar imágenes

Descripción Descarga una imagen desde un registro remoto (registry) al almacenamiento local. Si no se especifica tag, usa :latest por defecto.
Sintaxis y ejemplos
# Sintaxis básica
$ podman pull [registry/]imagen[:tag]

# Descargar imagen de Rocky Linux 9
$ podman pull rockylinux:9

# Descargar desde registry específico
$ podman pull docker.io/library/nginx:latest

# Descargar versión específica
$ podman pull quay.io/centos/centos:stream9

# Listar imágenes descargadas
$ podman images
REPOSITORY TAG IMAGE ID CREATED SIZE
rockylinux 9 a1b2c3d4e5f6 2 days ago 176 MB
Flags útiles --arch especifica arquitectura (amd64/arm64)
--quiet / -q solo muestra el Image ID
--tls-verify=false para registries sin TLS
Buscar imágenes $ podman search nginx
Busca en todos los registros configurados en /etc/containers/registries.conf
Comando #2

podman build — Construir imágenes

Descripción Construye una imagen personalizada leyendo instrucciones de un Containerfile (o Dockerfile). Cada instrucción crea una capa inmutable.
Containerfile ejemplo
FROM rockylinux:9
RUN dnf install -y nginx && dnf clean all
COPY index.html /usr/share/nginx/html/
EXPOSE 80
CMD ["nginx","-g","daemon off;"]
Comandos de construcción
# Build básico (punto = directorio actual)
$ podman build -t mi-nginx:1.0 .

# Especificando Containerfile
$ podman build -t mi-nginx:1.0 -f Containerfile .

# Sin caché (fuerza rebuild completo)
$ podman build --no-cache -t mi-app:latest .

# Ver historial de capas
$ podman history mi-nginx:1.0
Instrucciones Containerfile FROM · RUN · COPY · ADD · ENV · ARG · EXPOSE · VOLUME · WORKDIR · USER · CMD · ENTRYPOINT
Comando #3 — El más importante

podman run — Ejecutar contenedores

Descripción Crea y ejecuta un nuevo contenedor desde una imagen. Equivale a podman create + podman start en un solo paso.
Ejemplos esenciales
# Contenedor simple (se elimina al salir)
$ podman run hello-world

# Interactivo con terminal (-i interactivo, -t tty)
$ podman run -it rockylinux:9 bash

# En segundo plano (-d), con puerto (-p host:container) y nombre
$ podman run -d -p 8080:80 --name mi-web nginx

# Con volumen persistente (-v) y contexto SELinux (:Z)
$ podman run -d -v /datos:/datos:Z --name db postgres:15

# Auto-eliminación al terminar (--rm)
$ podman run --rm -it alpine sh

Comandos #4 · #5 · #6

start · stop · restart — Control de estado

▶ podman start
Inicia uno o más contenedores ya existentes que están detenidos.
podman start [nombre|ID]
⏹ podman stop
Envía SIGTERM al contenedor. Espera 10s y si no para, envía SIGKILL.
podman stop [-t secs] [nombre|ID]
🔄 podman restart
Detiene y vuelve a iniciar el contenedor. Útil para aplicar cambios de config.
podman restart [nombre|ID]
Gestión de estado
# Detener contenedor (espera 10s por defecto)
$ podman stop mi-web

# Iniciar contenedor detenido
$ podman start mi-web

# Reiniciar contenedor
$ podman restart mi-web

# Stop con timeout personalizado (5 segundos)
$ podman stop -t 5 mi-web

# Detener TODOS los contenedores activos
$ podman stop $(podman ps -q)

# Ver todos los contenedores (activos e inactivos)
$ podman ps -a
CONTAINER ID IMAGE COMMAND STATUS NAMES
a1b2c3d4e5f6 nginx nginx -g Up 2h mi-web
⚠️ Señales Linux podman kill -s SIGKILL mi-web — fuerza terminación inmediata sin esperar.
podman pause mi-web / podman unpause mi-web — congela/descongela procesos.
Comandos #7 · #8 · #9

exec · logs · inspect — Inspección

exec — Ejecutar comandos dentro del contenedor
# Abrir shell interactiva en contenedor en ejecución
$ podman exec -it mi-web bash

# Ejecutar comando sin shell interactiva
$ podman exec mi-web cat /etc/nginx/nginx.conf

# Para contenedores sin bash, usar sh
$ podman exec -it mi-web /bin/sh
logs
# Ver logs del contenedor
$ podman logs mi-web

# Seguir logs en tiempo real
$ podman logs -f mi-web

# Últimas 50 líneas
$ podman logs --tail 50 mi-web
inspect
# JSON detallado del contenedor
$ podman inspect mi-web

# Formato legible con Python
$ podman inspect mi-web | python3 -m json.tool

# Solo un campo específico
$ podman inspect --format="{{.State.Status}}" mi-web
Comandos #10 · #11

push · rm — Publicar y limpiar

podman push — Subir imágenes Envía una imagen local a un registry remoto. Requiere autenticación previa con podman login.
push
# 1. Autenticarse en el registry
$ podman login docker.io

# 2. Etiquetar con nombre completo del registry
$ podman tag mi-nginx:1.0 docker.io/usuario/mi-nginx:1.0

# 3. Hacer push
$ podman push docker.io/usuario/mi-nginx:1.0

# Registry privado (quay.io, Harbor, etc)
$ podman login quay.io
podman rm / rmi — Eliminar rm elimina contenedores (deben estar detenidos).
rmi elimina imágenes locales.
rm / rmi / limpieza
# Eliminar contenedor detenido
$ podman rm mi-web

# Forzar eliminación (aunque esté corriendo)
$ podman rm -f mi-web

# Eliminar TODOS los contenedores parados
$ podman rm $(podman ps -aq)

# Eliminar imagen
$ podman rmi mi-nginx:1.0

# Limpiar todo lo no utilizado
$ podman system prune
